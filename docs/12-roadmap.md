# Маршрут обучения: от запуска к самостоятельному backend

Цель — уметь объяснять решения и строить собственные функции. Скорость зависит от опыта; этапы ниже — ориентир на 8–12 недель при регулярной практике, а не обещание срока трудоустройства.

## Как работать каждый день

Выделите время на чтение, эксперимент и объяснение результата. После каждого урока закройте текст и ответьте: что произошло, где находится код, что будет при ошибке? Ведите короткий журнал: гипотеза → проверка → наблюдение. Если забыли синтаксис, найдите справку; если не понимаете модель происходящего, уменьшите пример.

## Этап 1. Python и инструменты

Урок 01. Освойте переменные, коллекции, циклы, функции, область видимости, импорт, исключения, классы, контекстные менеджеры, `Decimal`, venv и Git. Дополнительно разберите mutable/immutable, итераторы, генераторы, декораторы и аннотации типов.

**Задание:** чистая Python-функция рассчитывает стоимость списка товаров, отвергает отрицательное количество и возвращает Decimal. Напишите примеры пустой корзины и невалидного ввода.

**Готовность:** самостоятельно создаёте окружение, устанавливаете зависимости и объясняете traceback.

## Этап 2. HTTP и Django

Уроки 02 и 04. GET/POST, URL, query string, тело, заголовки, cookie, status code, redirect, DNS/TCP/TLS на уровне назначения. Django request → middleware → URL → view → response.

**Задание:** добавьте страницу «О проекте» через URL, view и шаблон с общей базой. Через DevTools объясните запрос регистрации и перенаправление после неё.

**Готовность:** можете проследить добавление товара от HTML-формы до session в БД и обратно.

## Этап 3. SQL и моделирование

Урок 03. SELECT, WHERE, JOIN, GROUP BY, ORDER BY; PK/FK, UNIQUE/CHECK, NULL, индексы, нормализация, миграции. Сначала напишите SQL на учебных таблицах, затем сопоставьте ORM.

**Задание:** добавьте бренд товара. Подготовьте миграцию, фильтр каталога, админку и тест. Для существующих строк спланируйте nullable/default, не вводите произвольный одноразовый default без понимания данных.

**Готовность:** объясняете N+1, разницу select_related/prefetch_related и что база защищает даже при обходе формы.

## Этап 4. Бизнес-правила и API

Уроки 05 и 06. Транзакции, изоляция, гонки, идемпотентность, object permissions, DTO/сериализация, пагинация. Запустите тесты на PostgreSQL и посмотрите, как блокировки отличаются от SQLite.

**Задание:** спроектируйте отмену заказа. Разрешите только владельцу и только из состояния NEW; верните остатки один раз, поддержите повтор запроса и гонку «отмена/отправка». Сначала запишите правила, затем тесты, затем реализацию. Просто менять поле status недостаточно.

**Готовность:** можете доказать отсутствие двойного списания/возврата, а не только показать удачный клик.

## Этап 5. Тесты и безопасность

Уроки 07–08. Проверки позитивных и негативных сценариев, отдельная тестовая БД, CSRF, XSS, SQL injection, горизонтальный доступ, пароли и секреты.

**Задание:** добавьте избранное с уникальностью пары user/product. Другой пользователь не должен получать или удалять вашу запись. Для HTML POST проверяйте CSRF, для API возвращайте последовательные ошибки.

**Готовность:** умеете написать failing test до исправления дефекта и объяснить, какую гарантию он проверяет.

## Этап 6. Развёртывание и эксплуатация

Уроки 09–11. Linux-процессы, порты, права файлов, env, Gunicorn, reverse proxy, TLS, Docker, CI, логи, health, backup/restore. CI-файл здесь — пример автоматизации; локальный зелёный запуск не означает, что GitHub Actions уже исполнился.

**Задание:** поднимите отдельную учебную PostgreSQL, восстановите туда backup и проверьте число заказов/суммы. Затем проведите безопасный учебный сбой базы и опишите диагностику.

**Готовность:** можете воспроизвести запуск на другой машине по своим инструкциям и восстановить данные.

## Дальнейшие самостоятельные проекты

Выберите один и доведите до работающего результата:

- сервис бронирования: пересекающиеся интервалы, отмена, часовые пояса, гонки;
- трекер задач команды: участники, роли, object permissions, поиск, история;
- библиотека: выдача экземпляров, сроки, очередь уведомлений;
- склад: журнал движений, инвентаризация, импорт CSV с отчётом ошибок.

Для проекта нужны модель данных, README, миграции, ограничения, тесты, CI и наблюдаемость. Не переносите магазин механически: сформулируйте инварианты новой области.

## Вопросы для самопроверки

1. Чем аутентификация отличается от авторизации?
2. Почему cookie не равна серверной сессии?
3. Где должна проверяться принадлежность заказа?
4. Почему GET не должен оформлять покупку?
5. Почему Decimal подходит деньгам, а float может ошибаться?
6. Когда выполняется ленивый QuerySet?
7. Что произойдёт, если в atomic возникнет исключение?
8. Что защищает UNIQUE, чего не защищает предварительный exists?
9. Почему повтор POST может создать второй заказ и как это предотвращать?
10. Почему цена в заказе хранится отдельным снимком?
11. Чем 400, 401, 403, 404 и 405 отличаются по смыслу?
12. Как узнать, что миграция безопасна для уже заполненной таблицы?
13. Почему SQLite-тест не доказывает PostgreSQL-блокировки?
14. Почему CORS не заменяет CSRF и авторизацию?
15. Что произойдёт с письмом, если процесс упадёт после commit?
16. Как проверить, что резервная копия действительно пригодна?

Не заучивайте ответы: найдите пример в коде и измените его входные условия.

## Карта тем за пределами этого проекта

Продолжите изучать структуры данных и сложность алгоритмов, сетевые протоколы, Linux, проектирование SQL, изоляцию транзакций, profiling, типизацию/mypy, DRF и OpenAPI, OAuth/OIDC, очереди, Redis, полнотекстовый поиск, observability, управление зависимостями и обновления безопасности. Изучайте их по необходимости и с практикой.

**Итоговое задание:** реализуйте новую функцию без копирования готового решения. Проведите ревью по четырём вопросам: корректны ли данные, защищён ли доступ, наблюдаемы ли ошибки, воспроизводим ли запуск? Объясните код другому человеку. Это более полезный критерий прогресса, чем число выученных названий библиотек.
