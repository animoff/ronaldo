# Python: язык, окружение и полезные привычки

**До начала:** установите Python и запустите проект по README. **Результат:** вы понимаете, какой интерпретатор выполняет программу, откуда берутся зависимости и почему денежные значения нельзя считать обычным `float`.

## Окружение — это набор конкретных инструментов

Исходный код — лишь одна часть приложения. Для выполнения нужны совместимая версия Python и зависимости. Виртуальное окружение изолирует библиотеки проекта: установка Django здесь не должна случайно обновить Django в другом проекте. Проверяйте интерпретатор, а не только название команды:

```bash
python --version
python -m pip --version
python -c "import sys; print(sys.executable)"
```

`python -m pip` запускает pip выбранного Python. В другом терминале окружение может быть не активировано. Ошибка `ModuleNotFoundError` часто означает именно это. Файл зависимостей задаёт воспроизводимый набор библиотек; установка пакета вручную без отражения в нём не помогает следующему разработчику.

## Что нужно знать в Python

Обязательно освоить переменные, условия, циклы, функции, словари, списки, множества, классы, импорты и исключения. Затем — итераторы, контекстные менеджеры и декораторы. В этом проекте они встречаются постоянно:

- словарь хранит данные корзины в сессии;
- класс `Product` описывает модель, а объект `Product(...)` — конкретный товар;
- декоратор ограничения HTTP-метода защищает view от неподходящего запроса;
- контекстный менеджер `transaction.atomic()` задаёт границу транзакции;
- импорт связывает модули; он сам по себе не выполняет HTTP-запрос.

Функция получает аргументы и возвращает значение. Она может иметь побочные эффекты: записать строку в БД, изменить сессию или отправить сообщение. Чем явнее такие эффекты, тем проще тестировать код.

```python
from decimal import Decimal


def line_total(price: Decimal, quantity: int) -> Decimal:
    """Посчитать стоимость строки, не обращаясь к базе данных."""
    if quantity <= 0:
        raise ValueError("Количество должно быть положительным")
    return price * quantity

assert line_total(Decimal("19.90"), 3) == Decimal("59.70")
```

Аннотации `Decimal` и `int` объясняют контракт читателю и инструментам. Python автоматически не запрещает передать другой тип: проверка входных данных остаётся обязанностью программы. Не путайте аннотацию с валидацией.

## Деньги и ошибки

`float` хранит двоичное приближение: `0.1 + 0.2` может отличаться от `0.3`. Для цен используем `Decimal`, а в модели — `DecimalField`. Создавайте `Decimal` из строки, а не из уже неточного `float`. В JSON суммы обычно передаются строками, чтобы клиент сам не потерял точность.

Исключение — сигнал, что обычный путь выполнения невозможен. Перехватывайте конкретную ожидаемую ошибку на подходящем уровне. `except Exception: pass` превращает настоящий сбой в молчаливый успех. Ошибка пользователя должна стать понятным сообщением формы; ошибка программы должна остаться видимой в тестах и журналах.

Не используйте изменяемые значения по умолчанию вроде `items=[]`: один список может случайно разделяться между вызовами. Для отсутствующего значения используйте `None` и создавайте список внутри функции.

## Практика

1. Запустите `python manage.py shell` и сравните `0.1 + 0.2` с суммой двух `Decimal`.
2. Выполните функцию выше с `quantity=0`. Прочитайте traceback снизу вверх: тип ошибки, сообщение, затем место вызова.
3. Найдите в `main/models.py` метод `save()`. Объясните, зачем он вызывает `super().save(...)`: без этого Python-код выполнится, но сохранение через ORM не произойдёт.
4. Напишите отдельную чистую функцию расчёта скидки и три проверки: обычная скидка, ноль, недопустимый процент. Продумайте округление.

**Проверка:** вы можете назвать путь текущего интерпретатора и объяснить разницу между строкой `"2"`, числом `2` и `Decimal("2.00")`.

**Типичные ошибки:** глобальная установка зависимостей, проглатывание исключений, смешивание строк и чисел, случайные запросы к БД при импорте модуля.
